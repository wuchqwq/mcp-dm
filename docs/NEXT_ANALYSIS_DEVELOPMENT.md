# 下一阶段：可探索、可修订的显微分析工具

> PR #26 收尾之后的开发方向。修复和已实现能力见各自提交；下文里程碑是计划，不是新增能力声明。开始前核对 GitHub 最新 main 与 PR，不重复拼接已合入的分支。关联 Issue #24。

## 产品定位与不变的边界

mcp-dm 给通用 Agent 提供可组合的观察、处理、测量、晶体学及模拟工具。Agent 根据研究问题和人类反馈组织分析；确定性计算和坐标变换由工具执行。不是固定 Python 判相流水线，不要求模型一次得出唯一答案。

研究者可以在 DM 中做一半，交给 Agent，取得受支持的科学结果再回到 DM；独立 TIFF、CIF/XYZ 不必绕道 DM。GUI 是共同观察、选区和纠正窗口，只修使用阻塞，不以布局、美化或新平台为目标。不同后端显式选择，不在 DM 失败后偷换计算来源。

## 收尾修复与仍然存在的缺口

本轮只修两个接续问题：

- 配准按已验证的 `scientific_grid_identity` 绑定，而不是把每次 gamma/频域显示修订的 wrapper ID 当作新科学输入。同一个频谱的显示变化可共同测量；真正新捕获、新帧、新 FFT 计算或不同科学 ROI 仍不混用。原视图、请求和标定来源仍保留。没有网格记录的历史测量继续采用严格旧契约，不能与新网格混用；已有旧配准只作历史查询，继续分析时生成新的 v2 绑定。
- `data_meaning` 是背景文字，不再因其非空就阻止用户对未知标量输入作明确的倒空间声明。必须仍有 `declare_reciprocal:true`、用户依据、尺度和单图作用域；保留先前文字，不从自然语言猜域。已确定的空间域、原生单位/Fourier 血缘、有效标定，以及已有 `reconstruction_type` 仍不能借此重解释。纠正重构类型属于另一个明确的语义修订任务，不在此补丁中。

仍未完成：普通 Agent 自主探索候选对应、失败原因的可操作反馈、中心/斑点定位误差、代表性真实数据的独立验证，以及一般同 ID 原地编辑的安全重新捕获。当前指向的 wrapper 也不等于全局“最新”状态。

## 里程碑 1：失败可诊断，探索不冒充确认（下一轮优先）

### A. 先记录超时发生在哪里

在现有请求和工作进程契约上增加有界阶段计时/状态，至少区分入队、进程启动、输入校验/读取、计算、结果持久化、响应交付。使用单调时钟计算阶段时长；stdout 仍只输出 MCP 协议。日志避免打印私有文件路径、数据或密钥。

对一个可重现例子，在同一代码/输入下分别测空闲和受控并行负载，保存正常与失败证据，再与未改动基线比较。不要只重跑到绿，也不要先放大所有 deadline。若只是测试互相争抢资源，调整测试调度并保留原负载实验；若普通使用也慢，针对实际瓶颈优化。客户端超时可能只是停止等待，必须能按原请求查询结果，不能自动重复产生副作用。

**验收：**一次有意触发的客户端超时和一次完成的调用都能说明阶段、原请求状态及下一步；恢复不重复计算/创建结果。不要把“无负载通过”宣传成并行性能已合格。

### B. 允许 Agent 提出候选，但把依据等级保留下来

当前 `structure_register` 仅接纳 user_confirmed/synthetic_fixture 对应。评估一种明确的“未确认候选”来源或独立探索入口，让 Agent 可先尝试结构/取向/反射对应、获取残差，再向研究者展示依据。复用现有数值算法，不放宽尺度、镜像、中心或畸变自由度。

探索结果永远不冒称用户确认、独立实验验证或唯一物相。确认应生成新版本；Agent 不能自行伪造确认来源。若候选/HKL 是看过全部点后挑出的，即使数值调用中没有用留出点拟合旋转，也必须说明留出点已参与模型选择，不能继续称其为未参与选择的验证数据。

没有足够反射时仍返回有限的候选或可解释拒绝，不要求用户先把整张图索引完。已知屏幕轴约定可由来源确定；未知镜像只能列为明确假设，不能悄悄择优。

**验收：**同一已固定输入分别走探索和真实用户确认路径，结果来源、候选状态、拟合与验证角色可区分；错误候选不能借重标定或增大容差变成成功。

## 里程碑 2：更少手工取点、更有用的失败反馈

围绕真实用例选一小批工具：有界局部峰定位/亚像素精化、批量重测、中心估计候选或残差诊断。优先复用已有定位代码及成熟数值库。保留原始选点、拟合模型、窗口、饱和/重叠/边缘诊断与未知误差；任意条纹或漫散射不强制拟合成孤立高斯点。

返回可核对的叠加图、对应表和未匹配反射；科学数组、显示映射和标注分开。区分输入/能力错误、状态过时、超时、拟合不一致和留出验证不一致，附上可行的下一操作。不要从某种残差图案直接断言第二相、孪晶或缺陷。

以现有对象和依赖提示确保修改中心/尺度后更新相关测量，保留旧版；纯显示变化不迫使重测。“继续当前分析”和“复查旧版本”明确区分，不另建任务数据库或自动规划平台。

## 里程碑 3：一份真实样例的连续使用验收

研究者在本地提供一份熟悉的 SAED 或实空间局部 FFT 样例、独立尺度依据、候选 CIF、少量有把握的反射。可以有未知项。先指定用于建立对应/配准的点，另留未参与拟合和候选挑选的点；模型选择看过验证点后应诚实降级证据，或另取验证观测。

完成：打开/捕获半成品 → 观察/取点 → 结构与晶带轴 → 模拟与对照 → 用户改变显示并纠正一点或中心/尺度 → 正确重测 → 保留不一致与多解 → 导出数值/图片/参数 → 在已支持范围内回到 DM。

这只是验收案例，不是固定分析顺序。缺实验样例时先完成合成开发，不等待数据才能推进。

真实数据只读。人工在 DM 同 ID 原地修改的再捕获，只用获授权的合成工作副本、独占宿主另行验证。新图接力、同 ID 编辑、并发编辑分别记录；查询旧 request 不是新观察。

## 仅在实际任务阻塞时扩展

按实测需要再安排 float32 TIFF、较大数值写回、更多 dtype/复数、性能/传输优化或高保真模拟。不能为通过现有限制静默量化、缩图或改单位；未知标尺仍允许像素域观察。

暂缓 GUI 重构、新聊天软件、VASP 执行、完整动力学模拟、大范围私有 ABI 探索及新通用调度层。现有原生导入仍限已资格确认的构建、有限二维 float32 与 nm/1/nm 范围；本路线不扩大其资格。

## 分工与交付

Codex 从集成后的 main 开独立分支，先做里程碑 1，再根据一个真实任务决定里程碑 2 的小增量。接口命名、实现方法和成熟库选择由 Codex 决定。代码、安装配置、内部 ID、误差计算和验收记录由开发 Agent 处理；研究者只提供数据依据、少量科学确认及真实操作反馈。

每个 PR 说明：新完成了什么实际操作，减少了什么手工步骤；是否复现失败及其原因；离线、实际 MCP、浏览器、DM 和真人验证分别到哪一步。原失败不擦除，数值门限不为测试放宽。只提交公开合成数据与代码，不提交实验原图、私有日志、厂商二进制或本机路径。

### 可直接交给 Codex 的起步任务

阅读本文和最新 AGENTS.md，先核实本收尾 PR 与 #26 是否已集成，不重复合并。首先完成可查询的阶段计时/失败诊断，以及不冒充 user_confirmed 的候选探索路径；它们复用现有 image/structure 工具，不建新平台、不优先做 GUI。随后选一个真实使用阻塞补局部峰定位、批量重测或对照展示。保持固定实验尺度、已知坐标约定、拟合/验证分离及不可变科学来源。用合成反例和实际 MCP 先验收；实验数据和 DM 试验只在获得授权后进行。分阶段推送新 PR，暂不自行合并 main。最终交付一个可连续修订的任务，而不是只列工具数或测试数。
