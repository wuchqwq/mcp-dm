# 交互式显微分析工作流：DM ↔ Agent（技术路线）

> **状态：产品方向与分阶段验收提案，不是已实现功能声明。** 它调整[项目路线图](../ROADMAP.md)的产品优先级；已实现能力仍以真实 MCP 状态、版本门禁和对应验收记录为准。尤其不能把 PR #12 的外部晶体学伴随工具或更大 FFT 当作本 PR 新增的运行时功能。

## 核心定位

mcp-dm 的目标不是一次就给出唯一晶体结构，也不是重写 DigitalMicrograph（DM）或另造聊天软件。研究者在 DM 中观察、选择图像或区域；通用 Agent 接收有身份、有标定的图像，协助**处理、预览、测量、标注、解释、修正和导出**。完整任务可以跨越多轮交流：研究者有权纠正选区、峰位、候选结构和文字解释。

ROI、线剖面、直方图、FFT、ASE 索引都只是基础能力；以**实际工作流是否顺畅**而不是工具数量或一次性判相准确率衡量进展。

## 应优先打通的用户故事

1. **看图与出图**：“把我 DM 里这张 ADF 图返回来。亮一点、压暗背景、调曲线；给我两版效果，我挑一版。”研究者看到的预览必须对应明确的图像和 ROI；改显示不改原始科学像素。
2. **局部 FFT 与标注**：“对我框出的区域做 FFT，增强弱反射和条纹，标出这几组频率。这个像图里的条带/拖尾，不要强制按单晶斑点索引。”生成易于核对和导出的 FFT 图、频率坐标和独立标注层。FFT 可以显示漫散射、条纹或多套反射，不能把它们都归为离散晶面。
3. **反复修改**：“这里的峰位偏了；换另一个中心；第二组反射可能来自孪晶，你把两组分别标一下。”保留前一版，明确更改的是显示、点位、ROI 还是科学假设；重新计算受影响的派生结果。
4. **缺陷与多域协作**：“比较界面两侧局部 FFT 的取向差异，标出可能的孪晶边界、层错区或异常条纹。”优先输出可检验的局部测量、取向差、区域标注与多个解释；二维投影本身通常不能证明完整三维孪晶关系或唯一缺陷类型。
5. **保存可复核结果**：“导出原始数值、增强显示图、带标注图和本次参数，便于我继续改。”输出新文件，支持继续加载和重编辑，严禁覆盖原图或伪称已写回 DM。

## 建议架构：复用 Bridge，增加薄的交互契约

| 层 | 职责 | 明确不做 |
| --- | --- | --- |
| DM / GMS 适配器 | 明确图像/文档/ROI 身份，读取真实图像与标定；在各自已验证范围内做 DM 原生裁剪、FFT、滤波及结果显示 | 猜前台窗口、绕过 ABI / 版本门禁、运行任意脚本或控制显微镜 |
| MCP 传输与交接 | 可视预览、受限科学数组交接、参数和操作回执、权限范围、错误与会话身份 | 把 PNG 当科学数值、超时后自动重复副作用调用 |
| 可选外部处理/可视化 | **独立副本**的显示映射、轻量绘图、编辑标注、有限科学分析；可采用 NumPy/SciPy/ASE 等现成库 | 冒充 DM 原生处理；把科学处理结果悄悄代替原始图；将依赖装入 GMS 自带 Python |
| Agent + 用户 | 连续引用同一已核验输入，提出可撤销操作，解释物理依据，接受用户纠正后更新派生结果 | 不经确认宣称模型看到了当前 DM 工作区；单张图自动给出唯一物相、孪晶或缺陷结论 |

**默认不另建独立聊天客户端或完整图像编辑器。** 先尝试在现有 Agent 客户端中返回图像/文件和可审查操作；只有真正证明客户端缺少必要标注交互时，再评估嵌入式查看器或可选 napari 窗口。DM 仍是研究者的原始工作台。

### 一、图像与身份：先把图可靠地传回来

- 选中**明确** image ID、源区域和版本/宿主会话。保留图像类型、轴序、像素尺寸、带符号比例尺、物理零点、单位和完整来源。DM 图像 ID 不是像素快照；旧 QUERY 只是历史回执。
- 同一个捕获对应两类输出：**可供人或多模态模型查看的 preview** 和 **保留 dtype、标定与哈希的科学数组**。两者不能互相代替；视觉理解须由实际客户端测试证明。
- 支持小区域到有界完整交接的渐进路径。大数据先降采样仅用于预览；需要定量时对确定的区域取原始数值，不让大图通过 MCP 文本无限灌入上下文。
- 外部分析不能将已导出的结果自动写回 DM。若未来需要写回或激活工作区，必须另有真实原生接口、所有权与授权验收。

### 二、显示配方与科学变换必须分开

**只改变显示（view recipe）**：黑白点、亮度/对比度、gamma、显示曲线、对数映射、色图、平移缩放、可见图层。保存明确参数和输入哈希；不会修改测量所用的科学数组。

**改变科学数据（derived data）**：高通、低通、带通、去背景、平滑、空间或傅里叶掩膜、FFT、IFFT、窗口函数等。它们可能改变强度、相位或频率峰形，应产生新的有来源的派生数组及其变换参数；不能因为输出“更好看”就当成原始测量结果。

优先复用具备相同语义的已资格确认 DM 原生接口；出图专用而且 DM 未接通的处理可以**经用户明确选择在外部处理副本**，记录外部库和参数，绝不静默降级或标为 DM-native。显示截图只作展示，不作衍射几何/FFT 的测量输入。

### 三、FFT 必须同时有数值底稿和显示图

- 明确源 ROI、边界、裁剪偏移、采样方向、源图空间标定、窗口函数/去均值等选择，保存原生 FFT 数值与数学频率网格。严格区分 DM 频谱显示中已知的半格偏移和数学 DC，区分 cycles/length 与 radians/length 的 2π。
- 分开保存：原生频谱 / power 等科学派生结果；log/gamma/contrast 等仅显示映射；点、矢量、拟合线、漫散射条纹、拟议双晶反射关系等可编辑标注层。不能在像素上烧录标注后当作原始 FFT。
- 对“条纹/拖尾/多组反射”的图片允许输出**候选条纹方向、长度与相对关系**、未确定的来源和多个候选域；不强迫所有强度特征通过孤立亮点检测，不能从一条拖尾直接宣称特定堆垛层错或孪晶面。
- 导出清晰、可复现的展示图（PNG、SVG 等）及数值（NPY+元数据）。图像宽高、注释颜色、字体和比例尺归显示配方；晶面间距和角度归单独测量结果。未实现 native SaveAs 时明说是外部导出。

### 四、把标注与多轮修订当一等对象

推荐先定义小型、可测试的会话/图层**数据契约**，不先建数据库或多 Agent 平台。

- **源与派生图层**：源图 ID/捕获哈希、每步操作及有界输出，所有计算引用明确输入；保存父子关系。
- **图层类型**：image、points、lines/vectors、shapes、text、region-labels。每个点或形状必须声明坐标系（源图像素中心、裁剪内坐标、FFT 网格、物理倒空间），必要时保留显示坐标到科学坐标变换；不能默默取整/裁剪。
- **科学注释语义**：用户确认的测量值 vs 算法提议的标记；候选 hkl/zone、双域或孪晶关系、缺陷与漫散射假设，以及证据、置信度限制和明确拒绝的候选要分别记录。
- **可修订状态**：针对同一已保存捕获保存 revision、操作类型、参数、前序引用、输出哈希和确认人。用户说“把这个点移两像素”时，只使受影响的测量/解释失效并重算，旧版仍可核对；禁止隐藏地对活体 DM 进行长时间轮询或对象编辑。
- **恢复语义**：本地输出须先持久记录请求和参数，再写新目录；核对文件完整性。对真实 DM 的未确定请求只查询原 ID，同一客户端会话的历史回执不等于实时界面状态。

这套轻量契约可以用 JSON sidecar 加可编辑 SVG 等文件验证，不要求一次完成大型 GUI。文件权限、敏感图像是否送往模型服务，仍取决于用户授权与客户端设置。

## 可借鉴的项目，而不是必须全装

| 项目 | 最值得参考的能力 | 建议 |
| --- | --- | --- |
| [napari 图像层](https://napari.org/stable/howtos/layers/image.html) 与 [图层体系](https://napari.org/stable/getting_started/layers.html) | 非破坏式 contrast/gamma、Image/Points/Shapes/Labels/Vectors | 借鉴图层数据结构与交互，先不要强制安装整套桌面 viewer |
| [HyperSpy Live FFT](https://hyperspy.org/hyperspy-doc/current/auto_examples/region_of_interest/fast_fourier_transform_live.html) | ROI 驱动的交互式 FFT、频谱与图像联动 | 参考“变 ROI→更新派生视图”行为与实验；不将其 FFT 偷换成已宣称的 DM 原生 FFT |
| [pyXem](https://www.pyxem.org/en/latest/) | 衍射斑点、标定、向量与多维电子衍射工作流 | 参考科学表示与检验思路，按实际任务选择集成 |
| [ASE](https://wiki.fysik.dtu.dk/ase/) / [orix](https://orix.readthedocs.io/en/latest/) | 晶胞/CIF、倒易基矢、取向/晶面指数 | 延续可选外部晶体学后端；不是图片显示 UI |
| [diffsims](https://diffsims.readthedocs.io/en/latest/) | 理论电子衍射图案的候选模拟 | 以后按需集成，先检查适用模型、依赖与 GPLv3 许可边界 |
| [Gatan DIFPack](https://www.gatan.com/products/tem-imaging-spectroscopy/difpack-module) | DM 自身的晶格、角度、衍射/FFT 标定与峰位精化工作流 | 用于功能/用户体验对照；不假定已安装或拥有可用 C++ ABI |

**对选型保留裁量：**先评估如何用现有工具与轻量渲染/保存得到连续体验，再决定是否引入 napari/HyperSpy 的运行依赖。新的 UI、插件或外部进程必须带来明确的可验收改善，而不是架构目标本身。

## 分阶段交付和验收门槛

### P0 — 图像真正“回到 Agent”，并可来回调整出图

在用户授权的合成图/副本上，由普通客户端明确选择 DM 图像/ROI，取得实际可查看的预览；两轮自然语言修改 contrast/gamma/曲线，比较前后图；同时导出显示配方、原始科学 NPY/标定和哈希。若客户端不能直接看图，不以“已产生 PNG”冒充成功，而应给出可打开的文件并记录限制。**验收指标：图像身份正确、显示可复现、不改原始像素、无需手写脚本。**

### P1 — ROI → FFT 出图 → 注释 → 用户修正 → 再导出

使用已有已验证 DM 原生 FFT 与外部可选视觉映射，在同一保存的 ROI 上出 FFT 图；支持点/矢量和漫散射条纹/双组反射候选标注。研究者修改一处中心、峰位、条纹或区域后生成新 revision 和可核对的 SVG/PNG+科学数据；先用含多组斑点和条纹的非对称合成例测试坐标，之后经授权选实验样本验证。**不要求自动判定单晶、孪晶或缺陷类型。**

### P2 — 受约束的多域/孪晶/缺陷证据组织

比较多个明确区域的局部 FFT、方向、周期、取向差、条纹分布、候选孪晶/层错几何；按需要接入 PR #12 的 ASE/SciPy 晶体学能力或其它经过评估的参考工具。明确镜像/投影/厚度/动力学衍射/CTF 等不确定性；用户可否定候选并保留理由。**验收指标是可核对的人机协作过程，不是第一次回答唯一相名。**

### P3 — 经使用证明必要的深度集成

仅当 P0–P2 遇到明确阻塞，才进一步考虑 DM 工作区激活、在 DM 原生文档中写入标注、原生 SaveAs/导入、完整 napari 插件、自动结构识别、更多 GMS 版本。每项都要有单独 ABI/权限/所有权或外部工具可靠性门禁。

## 验证标准及任务分工

- **独立测试**：带标定的非对称图、非整数 ROI、缩放预览映射、中心偏移、频率轴符号/单位、FFT 中条纹与重叠反射、标注修订前后对齐、源图 bitwise 不变、展示参数重放、缺失标定时拒绝虚构 d。
- **真实 DM 与普通 Agent**：同一确定会话里对比数值捕获、可视返回、原生 FFT、结果显示/导出；真实宿主试验需单人独占且明确授权。严格分离离线、实机数值、模型真正看图、人工标注和科学解释的资格。
- **科学语言**：条纹/漫散射可能来自缺陷、有限尺寸、双域、厚度/成像等多种成因。单个局部 FFT 的二维投影不证明完整孪晶律、缺陷分类或相分数。
- **项目指标**：完成一项实际图像出图与标注所需的人为步骤、修改轮数、可复现程度，以及测量/候选的可追溯性；不以 MCP 工具数量、测试断言总数作主指标。
- **协作**：Codex 主持产品集成/回归；DeepSeek 仅调查被具体用户工作流阻塞的原生 ABI；真实 DM 同时只有一个测试会话负责人。PR #12 / #13 仍有独立评审，先按 GitHub 最新状态处理依赖，不能把其运行时能力预先写成 main 已完成。

项目继续只处理**采集后的材料显微数据**，不控制相机、束流、样品台或光学系统，不隐藏本地/云端数据传输，不将模型的文字判断当作科研事实。
