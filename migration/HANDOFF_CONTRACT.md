# 跨仓科学交接：保持现有数据合同，不共用私有对象

本次不发明新的“通用科学 schema”。继续使用现有已支持的 schema-1 numerical
capture、校验器和明确的 MCP 工具输入。目录和 schema 名称保留兼容，不因为
删去 DM 依赖就改写旧数据含义。

**DM 端负责**实时图像/文档/选区 ID，GMS 版本资格，native session/request_id、
原操作及参数、查询状态、保留引用与实际宿主结果。超时后只按该端原请求查询，
不由科学端重新发一次创建/导入操作。

**科学端负责**独立数组、选帧/ROI、FFT、显示/标注、结构及模拟、测量和分析修订。
AnalysisContext 只引用这些有来源的对象；它不是 DM 请求日志的第二份权威副本。

**跨边界的包必须保留**：数值类型和真实 NPY 内容、轴顺序、实/倒空间域、带符号
标定和原点、单位及未知项、原源/帧/ROI/FFT 身份、来源与文件哈希、软件/算法
参数和原请求回执。显示 PNG 只能供观察，不能替代科学数组。文件一致性并不证明
可变 DM 图像曾被原子地捕获，也不证明物相解释正确。

`tools/verify_native_region.py` 是纯文件验证，保留它不意味着必须安装 DM。
小型 stdio/schema/registry 代码及此校验器可以作为两边各自带版本/哈希的协议
快照；没有跨仓源码 import。未来改变 wire/data 语义必须有兼容测试与明确版本，
不能只升级一个消费者后宣称所有历史捕获自动适用。

客户端明确选择科学计算或 DM 原生操作，不按操作系统猜后端；native 失败不会
自动改成 NumPy 并沿用“DM 结果”的标签。两者都安装时也只是增加可选工具。

本机已授权数据通过明确路径交接。跨 Mac/Windows 网络传输、认证、路径映射和
远程 MCP 暂未实现，不把 Python loopback 或 Windows named pipe 暴露到公网。
